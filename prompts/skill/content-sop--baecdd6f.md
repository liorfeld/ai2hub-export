## 1. שער בטיחות והיתכנות (Safety & Logic Gate)

**רץ לפני כל יצירה.** המודל מסווג את מילות המפתח/הכותרת:

| | |
|---|---|
| ✅ **מאושר** | סקירות מוצרים · מדריכים · השוואות · טיפים · מאמרי דעה בנישה |
| ⛔ **נדחה** | "אודות" · "מדיניות פרטיות" · "תקנון" · ייעוץ משפטי/רפואי מחייב |

**כישלון ⇒ עצירה מלאה** + לוג: `Safety Check Failed: Non-Content Topic`.

---

## 2. איכות ואופי התוכן

### 2.1 סטנדרטים

- **היקף:** 1,200–1,700 מילים (מינימום).
- **אימות מידע — קריטי:** כל עובדה/נתון/טענה חייבים להיות מאומתים. בספק — להשמיט או לסייג.
- **מקוריות:** Plagiarism Check לפני פרסום.
- **קריאוּת:** פסקאות מלאות ומעניינות, מרווחים נעימים. **לא** שורה בודדת לפסקה.
- **גישה — "המגשר":** מתווך אובייקטיבי שמספק ערך ומידע אמין.
  - ❌ טון של איש מכירות אגרסיבי
  - ❌ גוף ראשון / "חוויה אישית"
  - ✅ בלוגריות רחבה ומלאה

### 2.2 קול המותג

| טון | מתי |
|---|---|
| מקצועי/סמכותי | מדריכים טכניים, סקירות עומק |
| חברי/בגובה העיניים | לייף-סטייל, בלוג אישי |
| ציני/שנון | כשמתאים לקהל ולנישה |

### 2.3 Evergreen vs. News

- **על-זמני** ("איך לנקות מכונת קפה") → **בלי שנה** בכותרת.
- **תלוי-זמן** (סיכום שנתי, מוצרים חדשים) → **השנה הנוכחית** בלבד.

## 3. מבנה ו-SEO

### 3.1 היררכיית כותרות

`H1` (אחד בלבד, מכיל מילת מפתח מרכזית) → `H2` (ראשי פרקים) → `H3` (תתי-נושאים) → `H4` (אופציונלי).
**איסור מוחלט על דילוג רמות** (H1 → H3 = פסול).

### 3.2 Meta & URL

- **Slug:** תרגום הכותרת לשפת המותג · lowercase · מקפים קצרים (`-`) · ללא תווים מיוחדים · **ללא מקף ארוך**.
  `"איך לבחור מכונת קפה"` → `how-to-choose-coffee-machine`
- **מילות מפתח:** ב-H1, בפסקה הראשונה, ובפיזור טבעי — **צפיפות 1%–2%**.
- **Meta Description (חובה):** עד **160 תווים** · מילת מפתח ראשית · הנעה לפעולה · תקציר מסקרן.

### 3.3 Schema Markup (JSON-LD)

| סוג תוכן | Schema |
|---|---|
| סקירה | `ReviewSchema` (כולל דירוג כוכבים) |
| מאמר כללי | `ArticleSchema` |
| מדריך | `HowToSchema` |

## 4. ויזואליה ומדיה

### 4.1 תמונות

- **כמות:** מינימום **3 תמונות גוף** + Featured Image.
- **מיקום:** כולן **ממורכזות**.
- **איכות:** ריאליסטיות, High-Res, לא קטנות, תואמות הקשר. **להימנע מתמונות לבנות** שנבלעות ברקע הבלוג.
- **פורמט:** WebP.
- **Featured:** תואמת לנושא, **לא ענקית** (לא 1280×1280) — לצמצם.
- **שם קובץ:** אנגלית + מקפים קצרים → `best-coffee-machine-2024.webp`
- **כיתוב:** מומלץ טקסט קצר בפונט קטן מתחת לתמונה.
- **אפילייט:** מומלץ שלחיצה על תמונה תוביל ללינק אפילייט.

**4 פרמטרים בוורדפרס — חובה לכל תמונה:**

| שדה | תוכן |
|---|---|
| `Title` | שם באנגלית (`Best-Coffee-Machine-Review`) |
| `Alt` | תיאור **בעברית** — נגישות + גוגל |
| `Caption` | כיתוב קצר שמופיע מתחת לתמונה |
| `Description` | תיאור מורחב לשימוש פנימי במדיה |

### 4.2 גרפיקה

תוכן שעוסק בנתונים/מגמות/השוואות → לייצר **גרף ויזואלי**.

## 5. UX & Formatting

לשבור את "קיר הטקסט". **חובה לפחות אלמנט אחד — ולגוון בין כתבות, לא לקבע פורמט:**

- **טבלאות** — השוואת מחירים, יתרונות/חסרונות, מפרט (לא חובה בכל כתבה)
- **רשימות** — ממוספרות/נקודות לפירוק תהליכים
- **Blockquote** — **חובה** לפחות ציטוט אחד או "טיפ מומחה" במסגרת מודגשת
- **גרפים ודיאגרמות**
- **כפתורי לינק מעוצבים** — אפילייט ו-CTA

---

## 6. קישורים ומונטיזציה

- **קישורים: מינימום 5**, משולבים אורגנית.
  - **פנימיים** — למאמרים אחרים בבלוג (SEO של האתר)
  - **חיצוניים** — מקורות סמכותיים (ויקיפדיה, חדשות גדולות, מחקרים) לחיזוק אמינות
- **CTA: 5–7 בכל כתבה** — כפתורים מעוצבים או לינקים בולטים, **לא טקסט רגיל**.
  - מיקום אסטרטגי: אחרי בעיה→פתרון · ליד תמונות מוצרים · בסוף כל סקירה
  - **פסקת סיכום מניעה** עם CTA בולט: "לבדיקת המחיר העדכני לחצו כאן"

---

## 7. פרסום ל-WordPress

- **Author Mapping** — User ID לפי הנישה, או ברירת מחדל.
- **Category Logic** — לנתח את הקטגוריות הקיימות באתר ולבחור המתאימה. אין התאמה → **"כללי"**.
- **Tags** — **2–3 בלבד** (יותר = סיכון שכפול תוכן).

# פונקציונליות המערכת

## סכמת נתונים

**`content_tasks`** — משימת מאמר:

| שדה | ערכים |
|---|---|
| `task_type` | `branded` · `non-branded` · `multi-brand` (ברירת מחדל `branded`) |
| `article_tone` | `sales` · `personal` · `enthusiastic` · `innovative` · `educational` · `comparative` · `professional` (ברירת מחדל) · `conversational` |
| `status` | TEXT, ברירת מחדל `pending` |
| `priority` | TEXT, ברירת מחדל `normal` |
| `language` | ברירת מחדל `Hebrew` |
| `affiliate_url`, `blog_id`, `context` | — |

> **פער ידוע:** ה-SOP מגדיר 3 טונים (מקצועי/חברי/ציני), ה-DB מגדיר **8**. ה-DB מנצח בפועל.

**`blogs`** — יעד פרסום: `platform` (ברירת מחדל `wordpress`) · `api_key` · `status` (`active`/`disabled`).
**`brands`** — מותגים. **`content_guidelines`** — ה-SOP הזה.

## גבולות גזרה

- **רשומה גלובלית אחת.** אין SOP per-brand ואין per-blog. עדכון = לכולם.
- **גרסאות בלי היסטוריה.** טריגר `increment_guidelines_version` מעלה `version` בכל UPDATE, אבל הטקסט הקודם **נדרס**. אין rollback.
- **RLS פתוח:** כל משתמש מחובר יכול לקרוא/לערוך/**למחוק** את הרשומה היחידה (`supabase/migrations/20260125_fix_guidelines_rls.sql`).
- **`content_en` עלול להיות מיושן.** `translation_status` תקוע `pending` בגרסה 8 — כלומר האנגלית שה-LLM מקבל היא מגרסה קודמת. להריץ `/api/guidelines/translate` אחרי כל עריכה.
- **טקסט חופשי, לא סכמה.** המערכת לא אוכפת שום כלל מכאן — האכיפה היא בפרומפט של n8n בלבד.
- **זיהום בטקסט הפרודקשן:** באמצע סעיף 1 תקועה המחרוזת `--- בדיקת שמירה ---` (שארית טסט). לנקות בעריכה הבאה.
