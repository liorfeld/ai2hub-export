# אבחון הבזקים ב-UI

כשמשהו "מהבהב" או "עולה רגע אחרת ואז מסתדר" — **אל תתחיל ממטמון, CDN או
רשת**. במקרה שממנו נולד ה-skill הזה שם הלכו שלוש שעות, והתשובה הייתה בשורה
אחת של CSS.

## הכלל

> **שאל איזו שכבה מחזיקה את האפקט, ומה עוד מזיז את השכבה הזאת.**

טיפול ויזואלי **קבוע** לא חולק אלמנט עם משהו **שמונפש**.

### המקרה הקלאסי

scrim (גרדיאנט שמכהה תמונה כדי שטקסט יהיה קריא) הוגדר כ-`background-image`
על אותו אלמנט שמחזיק את הטקסט. מעבר בין מסכים מעלים את הטקסט — **וה-scrim
נעלם איתו**. התמונה קפצה לבהירות מלאה למשך כל המעבר וחזרה בסוף.

```css
/* לפני — האפקט מת יחד עם הטקסט */
.copy { background-image: var(--scrim); transition: opacity .15s }

/* אחרי — שכבה קבועה, וטקסט חופשי לזוז */
.scrim { position:absolute; inset:0; z-index:3; background-image:var(--scrim) }
.copy  { position:absolute; inset:0; z-index:4 }
```

### איך מוכיחים ב-30 שניות

לדגום את שתי האטימויות במהלך המעבר האמיתי:

```js
setInterval(() => log(
  getComputedStyle(document.querySelector('.scrim')).opacity + '/' +
  getComputedStyle(document.querySelector('.copy')).opacity), 120)
```

`1/0.44 · 1/0 · 1/0 … 1/1` = תקין. אם שניהם יורדים יחד — זה הבאג.

## סדר אבחון

1. **שכבות** — מי מחזיק את האפקט, ומה מנפיש אותו
2. **סדר צביעה** — האם ה-CSS הוחל לפני הצביעה הראשונה
3. **מצב JS** — האם משהו מוסתר עד שסקריפט רץ
4. **מטמון** — רק אחרי שכל השאר נשלל

## ארבע מלכודות סמוכות

**`@import` מבטל חסימת צביעה.** `styles.css` שמכיל רק ייבואים גורם לדפדפן
לחשוב שהגיליון נטען, לצייר בלי עיצוב, ואז לקפוץ. תגי `<link>` מקבילים.

**נכסים בלי גרסה = שינוי שלא מגיע.** קובץ עם מטמון-קצה של 30 יום תחת אותו
שם פשוט לא מתעדכן. `?v=<hash>` על CSS, JS **ותמונות**. התסמין: "אני לא רואה
שום שינוי בכלל".

**שער-JS על תמונה מאחר אותה.** `type="module"` הוא מושהה. הסתרת התמונה עד
שהוא רץ גורמת לה להגיע **מאוחר יותר** ואז לקפוץ. סקריפט inline סינכרוני.

**LQIP יוצר את ההבזק שהוא נועד למנוע.** תצוגה מקדימה מטושטשת = קפיצה
מטושטש→חד. אם ממילא מסתירים עד שהתמונה מוכנה — היא מיותרת.

## נגזרת לא דורסת מקור

צינור שכותב חזרה על הקלט שלו הוא באג. סטילס שנדרסו בפריימים מתוך H.264 ירדו
ל-**SSIM 0.943** מול המקור — מקטעי 8×8 על עור, ריסים מרוחים — כדי לשכלל
פריים בודד שאיש לא רואה. שמור מקורות נקיים **מחוץ לנתיב הכתיבה**.

## מדידות שכדאי להכיר

- שני קידודי H.264 של **אותו** פריים: SSIM ~0.977. פריימים **במרחק 6**:
  ~0.9995. כלומר סף SSIM מוחלט לא מבחין בין "פריים נכון" ל"פספוס של 6".
  בדיקה יחסית (יותר דומה ליעד מאשר לצד השני) עובדת.
- WebP לא תמיד עדיף: מול פריים חסר-אובדן, `jpeg -q:v 1` נתן 0.998 ב-117KB;
  `webp q94` נתן 0.995 ב-108KB.
- נעילת קלט ש**מוחקת** לחיצות במהלך מעבר מרגישה שבורה. לשמור את הכוונה
  האחרונה ולבצע כשמתפנה.
